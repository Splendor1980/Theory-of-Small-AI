## Ключевые идеи (внешнее ревью + моё согласование)
Все три складываются в «конвейер»: скелет + объяснённая ошибка + чистый контекст -> headless-проверка -> память.

1. **Error Explainer** (БРАТЬ, высший приоритет)
   - Регекс-маппинг логов Godot -> человеческая инструкция, понятная микро-модели.
   - Пример: Identifier X not declared -> «ты использовал X, но забыл 'var X'».
   - Сокращает итерации петли с 10-15 до 1-2.
   - Дополнительно: детектор зацикливания (одинаковая ошибка N раз -> сменить скелет, не мучить модель).

2. **Скелеты / AST-паттерны** (УЖЕ ЕСТЬ как движок, расширять)
   - Хранить «пустые скелеты» под задачи (передвижение, стрельба, патруль).
   - Модель заполняет только внутренность функции, остальное не трогает.

3. **Лоботомия контекста (Sliding Window)** (БРАТЬ)
   - На каждой итерации ошибки стирать неудачный код; слать чистый [система]+[задача]+[ошибка].
   - Контекст держать 512-1024 токенов; CPU не захлёбывается.

## ПРИНЯТО: настраиваемость + облачная сборка APK
Согласовано с пользователем по итогам разбора ограничений заготовленных шаблонов.
1. **Настраиваемость (логика + тема).** Разделить каждый шаблон на:
   - движок/логику (не меняется),
   - тему/конфиг (имена, текстуры, цвета, шрифт, текст).
   Тогда «шашки=кошки и собаки», «кристаллы=конфеты», «фон/шрифт» = правка конфига,
   а не кода. ОБРАЗЕЦ: крестики-нолики.
   Решение для схемы (а)+(б): десятки категорий-движков + темы, не сотни шаблонов.
2. **Графика:** шаблон = «пустой движок» (примитивы draw_*), красота приходит из темы/ассетов
   (подтягиваются из интернета или генерируются). Текущий уровень (Денди/Сега) — промежуточная стадия.
3. **Сборка APK — облачная (CI/CD), НЕ на слабом ПК.**
   - GitHub Actions (free): VM Linux уже с JDK; ставим Godot headless + Android SDK;
     yes | sdkmanager --licenses ; godot --headless --export-release Android apk.
   - На той же VM: godot --headless --check-only (настоящая проверка синтаксиса) + автотесты.
   - Бонус: CI закрывает сразу два отложенных пункта (Godot headless + сборка APK).
   - Вариант 2 (локальный CLI без Android Studio) — только fallback, если нет CI/интернета.
4. **Роль мини-LLM:** не «всё», а «хвост» за пределами полки шаблонов (нестандартная логика).
   Полка закрывает стандарт. Блокируется только сломанным pip.

## CI workflow (черновик) — .github/workflows/build-apk.yml
- runs-on: ubuntu-latest
- установка Godot headless (скачать godot .x86_64.zip, распаковать)
- java: установить JDK (temurin 17)
- Android SDK: commandlinetools + yes | sdkmanager --licenses
- экспорт: godot --headless --export-debug "Android" android.apk (или --export-release)
- отдельный job/job-step: godot --headless --check-only по всем .gd
- upload-artifact: apk

   - Проверено: «крестики-нолики»→classic; «как кошки и собаки»→cats_dogs;

2. **CI-workflow (.github-черновик).** `agent1/ci/build-apk.yml`:

   - job `build_apk`: JDK17 + Android commandline-tools/SDK + godot --export-debug Android → game.apk.
   - upload-artifact. Лежит как шаблон; философия «не грузить слабый ПК».

  Идея — workflow_dispatch-input (по умолчанию «змейка на конфетах»).

## ГУГЛ-рецепт (внешнее ревью, принято)
Ключевые пункты от гугла, на которые опирается CI:
1. Экспортные шаблоны ОБЯЗАТЕЛЬНЫ: папка `~/.local/share/godot/export_templates/4.2.2.stable`
   строго по версии исполняемого файла; без них `--export-debug` падает.
2. Godot сам подставляет `${VAR}` из export_presets.cfg из env Linux (раздел env: шага GHA).
3. `--headless` заменяет старые серверные сборки; корректно работает с --export-debug без X11.
4. debug.keystore можно сгенерировать на лету keytool'ом в CI (storepass android / androiddebugkey / android).
5. Небольшая развилка: гугл считал точку входа через `run/main_script` + `extends SceneTree`;
   мы используем `run/main_scene` + хост (Node2D), т.к. собираем НАСТОЯЩИЕ Node2D-игры из шаблонов.

## Отложено/не берём (сейчас)
- Эволюция через XOR гипервекторов (оверинжиниринг; реальная эволюция = мутация AST).
- WebAssembly-агенты (Wasmtime/Wasmer) — задача отсутствует, ломает zero-dependency.
- Микро-LLM (GGUF) — ТЕПЕРЬ не «если понадобится», а НУЖЕН для произвольных игр
  и «болталки»; НО pip сломан в этой среде (ensurepip не закрепляется) -> препятствие.
- Godot headless — нужен для полной проверки синтаксиса (сейчас fallback-валидатор).

## Философия
- Только stdlib Python (нет pip-зависимостей).
- RAM, не VRAM (i5-3450, 16GB — слабый CPU и RAM).
- Минимум сущностей, максимум прагматизма.
